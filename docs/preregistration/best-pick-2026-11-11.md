# Preregistration: a card's best pick (Step F, written 2026-11-11)

Status: **binding from the commit that first adds this file.** Paper only: nothing here goes on a card, a ticket or the
review skill. The rule is recorded at each card's send time and judged once, on new games, by the test in section 7.
Written without looking at any game result after 2026-11-11 21:00Z and without computing the rule's performance on any
game (old or new). Amendments are allowed only before the first counted record exists, with the date and the owner's
words; after that, none (section 9).

## 0. Limits, stated first
- The hypotheses H1–H7 were found on the same 297 cards (Oct 17–Nov 10) they were counted on, out of many looks. They are
  candidates, not facts. Most will probably fail on new games.
- n = 100 named picks per sport can only detect a large edge. With the sportsbook expecting about 75% for the named picks,
  a one-sided 5% test needs roughly 7 more wins than expected out of 100 (about +7 points) to pass. A real but small edge
  will read as "drop".
- The comparison with the highest-sportsbook-% pick is on raw wins. That pick is, by construction, the sportsbook's
  favourite on the card, so beating it on hit rate is a hard bar. The owner asked for it; it stays.
- Only NBA winner picks and NHL puck-line picks can reach the floor (section 4). Every other market is recorded and never
  named.
- NFL and soccer: record only, name nothing (section 8).
- Win counts only. No profit claim follows from any result here.

## 1. Units, time and "new games"
- **T0** = the committer timestamp of the git commit that first adds this file
  (`git log --diff-filter=A --format=%cI -- docs/preregistration/best-pick-2026-11-11.md`).
- **Card** = one NBA or NHL game card that the delivery job (`app.telegram.run_once`) actually sent (`deliver_card`
  returned `sent`). Send time = the report's `as_of` used to build that card.
- **Counted card**: sent at or after T0, for a game whose `tipoff_at` is after T0, and recorded live at send time by a
  recorder whose stored `prereg_sha256` equals the sha256 of this file. If a game has more than one sent card, only the
  earliest-sent one counts. Nothing is reconstructed afterwards: a card without a live record does not count
  (no backdating). Cards are counted only from the recorder's release onward.
- Information used = what the card job could see at its send time: the card's own report
  (`RealProvider(store, as_of).ranked_picks(...)`, the same object the card is built from), the store's quotes with
  `retrieved_at` at or before the pick's `generated_at`, `games` rows (the schedule), and `lineup.facts(conn, sport, games,
  as_of)`. No result, quote or report retrieved after send time.

## 2. Candidates (per card)
A pick of the card's game is a **candidate** when all hold:
1. market is in NBA {winner, spread, total} or NHL {winner, spread, total, reg3} (team totals excluded: no hypothesis,
   no sportsbook price);
2. `probability` (app) and `market_prob` (sportsbook, de-vigged, as `ranked_picks` returns it) are both present;
3. `lineup.review_flags(sport, pick, facts[game_id])` returns an empty list. "Lineup facts unavailable" or any exception
   counts as a flag. **A pick with a lineup flag is never named.**
4. Not AVOID on its exact live record: excluded when `percentage_history.rank` is not None and
   `percentage_history.losses > percentage_history.wins` (the card's own AVOID). Only the live exact-percentage record
   (`threshold_overview.percentage_record`, as of send time) is used; the recomputed past-seasons `history` and any
   tuned season never count.

All percentages below are the **displayed** values, `threshold_overview.displayed_percentage(p)` (one decimal, half-up),
compared as decimals. "Book %" = displayed `market_prob` of the picked side; "app %" = displayed `probability`.

## 3. Score (H1–H7 only; each item +1, -1 or 0; score = sum)
Same-game picks below are the other picks of the same card's report (same `game_id`); sides are `percentage_history.side`
(`a` = home, `b` = away for winner/spread/reg3; `mid` = draw for reg3).

NBA winner
- H1: book % >= 72.0 → +1; book % <= 58.0 → -1.
- H2: app % < book % → +1; app % - book % >= 5.6 → -1.
- H3: the same game's NBA spread pick is on the other side → +1; the same side → -1; no spread pick → 0.
- H4: movement = book % now - book % at opening, for the picked side. "Now" = the quote `market_prob` came from (latest
  moneyline retrieved at or before `generated_at`, the app's `_winner_quote_prob` query). "Opening" = the stored
  moneyline of the same game with the earliest `retrieved_at` at or before `generated_at` (ties: `price_label='open'`
  first, then lowest `quote_id`); its de-vigged home probability turned into the picked side and displayed to one decimal.
  movement >= +3.0 → +1; movement <= -3.0 → -1; else 0 (one quote only → 0).

NHL spread (puck line)
- H5a: picked team equals the same game's NHL winner pick → +1; different → -1; no winner pick → 0.
- H5b: app % >= 67.0 → +1.
- H5c: the picked team played the previous day → -1.

Totals (NBA and NHL)
- H6: either team played the previous day → -1. (No positive item.)

NHL reg3
- H7: the same game's NHL winner pick has app % >= 60.0 and the reg3 pick is the same team → +1; otherwise (below 60.0,
  a draw pick, the other team, no winner pick) → -1.

NBA spread, NHL winner: no hypothesis, score 0.

"Played the previous day": the team has a `games` row (home or away), status not `postponed` or `canceled`, whose
`tipoff_at` falls on the America/Toronto calendar date one day before this game's America/Toronto date. Schedule rows
exist before the game, so this is known at send time.

## 4. The named pick, the floor and ties
- **Floor: score >= 2.** Below it the card's best pick is "none stands out".
- Named pick = the candidate with score >= 2, ordered by: higher score; higher book %; higher app %; market order
  winner, spread, total, reg3; lower `forecast_id`.
- Consequence (by construction, not by data): only NBA winner (max +4) and NHL spread (max +2) can be named.

## 5. Baseline: "highest sportsbook % on the card"
For every counted card: among the same candidates (section 2, same lineup and AVOID exclusions), the one with the highest
book %; ties: higher app %, market order, lower `forecast_id`. Recorded on every card, named or not.

## 6. Grading
- Each named and baseline pick is graded by the app's own settlement of its recorded `forecast_id`
  (`markets.settle` with that forecast's line, as `scripts/best_picks.py` does), read at evaluation time.
- Decided = win or loss. Push, void, unscorable: not decided, excluded from every rate and test, and counted.
- Expected rate of a named pick = its unrounded `market_prob` recorded at send time.

## 7. Test and decision (per sport, NBA and NHL separately)
- **Evaluation set**: the first 100 named picks, in send order, whose grade is decided. Evaluated **once**, when the 100th
  of them is decided and every earlier named pick has a final grade.
- **Test A (vs the sportsbook's own expectation)**: W = wins in the set; p_i = recorded `market_prob` of each. One-sided
  exact Poisson-binomial p-value P(X >= W) with X = sum of independent Bernoulli(p_i). Pass if p < 0.05.
- **Test B (vs the baseline, paired)**: on the set's cards where the baseline is a different pick and is decided:
  b = named won and baseline lost, c = named lost and baseline won. One-sided exact binomial (sign/McNemar) test,
  P(Bin(b + c, 0.5) >= b). Pass if p < 0.05. b + c = 0 → fail.
- **Keep** (the rule may then be proposed for the card, which still needs review and the owner's go): Test A **and** Test B
  pass. Anything else → **drop** for that sport.
- **Deadline**: if a sport has not completed its evaluation set by 2027-06-30 23:59Z, the result is "too few games" and
  the rule is dropped for that sport.
- Reported with the decision, not deciding: W/100 with Wilson 95% interval, mean expected rate, b and c, number of cards
  counted, number named, excluded by lineup flag, by AVOID, pushes/voids, cards sent without a record.

## 8. NFL and soccer
Steps D/E have not given either sport a rule. Their cards are recorded with the full picture (every pick, app %, book %
when present, exact live record) and **no pick is named**. Any rule for them needs its own preregistration, committed
before its own new games.

## 9. Integrity
- **No interim looks.** Before a sport's evaluation set is complete, reports show only counts (cards recorded, named,
  decided); no wins, losses or rates of named or baseline picks.
- No change to the rule, floor, tie-breaks, markets, test, alpha, n or deadline after T0. No subgroup, other market or
  other floor is promoted from these games; they may only seed a new preregistration whose own counting starts after its
  own commit.
- A recorder defect found later: every record written by the defective version is excluded, whole (all rows of that
  version, regardless of outcome), decided and written in HANDOFF.md before any result of those rows is read.
- The history line (`Past seasons, recomputed, model line`) and any season a model was tuned or selected on never feed the
  rule, the AVOID check or the test.
- H8 is not used. The book-% tie-break is a neutral ordering choice made here.
